# PaySurity Platform — Test Tenant & Seed Data Reference
**Document Type:** Implementation Reference — Agentic Developer Seed Specification  
**Version:** v1.0 | **Date:** 2026-03-12  
**Standard:** Follows `DEV_IMPLEMENTATION_STANDARD.md` — no hardcoded values, all configurable data in DB

---

## Overview

This document defines the **canonical test tenant (BistroBeest)** used as the reference implementation for all seed data across the PaySurity platform. Every vertical's seed file uses BistroBeest as the demo merchant, ensuring:

1. Day-1 database contains real, usable data (not empty tables)
2. Developers can run the platform locally and see a working tenant immediately
3. QA has a stable reference tenant for regression testing
4. Sales demos run against real seeded data, not mocked API responses

**BistroBeest.com** is the restaurant POS vertical's flagship product brand AND the reference test tenant. It is a fictional but fully realistic restaurant group used throughout all seed data.

## Naming Conventions for Test Data

All seeded UUIDs use a deterministic pattern so developers can rely on them in tests:

| Entity | ID Pattern | Example |
|---|---|---|
| Legal Entity | `11111111-1111-...` | Holding company |
| Tenant | `aaaaaaaa-aaaa-...` | BistroBeest tenant |
| Brand | `bbbb000N-...` | Brand N |
| Location | `loc0000N-...` | Location N |
| User | `usr0000N-...` | User N |
| Category | `cat0000N-...` | Category N |
| Item | `item000N-...` | Menu item N |
| Tier | `tier000N-...` | Loyalty tier N |
| Template | `tmpl000N-...` | Notification template N |

These fixed IDs are for **development and staging only**. Production generates UUIDs via `gen_random_uuid()` on every insert.

## Environment Guard Pattern

All test/demo data is guarded against production insertion:

```sql
-- Pattern used throughout seed files for user/PII data:
DO $$ BEGIN
  IF current_setting('app.environment', TRUE) IN ('development', 'staging') THEN
    -- Insert demo users, test transactions, etc.
  END IF;
END $$;

-- Config and reference data (no PII) always seeds in all environments:
INSERT INTO platform_config (...) ON CONFLICT (key) DO NOTHING;
```

The `app.environment` session variable is set by the migration runner based on the `APP_ENVIRONMENT` environment variable. It is never hardcoded in SQL.
