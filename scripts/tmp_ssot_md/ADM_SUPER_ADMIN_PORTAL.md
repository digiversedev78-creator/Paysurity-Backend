## CRITICAL ARCHITECTURAL BOUNDARY
This document strictly enforces the segregation of concerns between the **Merchant Dashboard** (`apps/merchant-dashboard`) and the **Super Admin Portal** (`apps/admin-portal`). Under no circumstances should internal operational tools bleed into the Tenant-facing applications. 

### Merchant Dashboard (Tenant Admin)
- Manages local `menu_items`, `employees`, `payroll`, `pos`, `orders`, `loyalty_accounts` strictly partitioned by their inherent `tenant_id`.
- Cannot view other merchants. Cannot manage Platform configurations (e.g. Master Gateway Keys).

### Super Admin Portal (Platform Staff)
- Has ubiquitous global access bypassing standard `tenant_id` Row-Level Security via the `x-impersonate-tenant` middleware tunnel.
- Controls the global network orchestration, automated deployments, merchant onboarding, sub-admin RBAC, and revenue extraction (PayFactor).

---

## Required Modules & Features

### 1. The Global Telemetry Dashboard
- Displays aggregated Gross Processing Volume (GPV), Total Active Tenants, Revenue Split Projections (PaySurity Cut vs Merchant Gross), and System Latency.
- Includes the **Affiliates Module**: The mathematical tracking of leads generated by internal PaySurity Sales/Resellers bringing new Merchants to the platform.

### 2. Physical Device Management (MDM / IoT Remote)
- Exposes a hardware matrix tracking every physical POS iPad `status` across all tenants.
- **Remote Diagnostics Tool:** Sub-Admins can click `FORCE REBOOT`, `CLEAR CACHE`, or `VIEW REMOTE SCREEN`. These commands dispatch securely over the `/mdm-remote` WebSocket Gateway bypassing standard internet firewalls.

### 3. Tenant Management & Impersonation
- Allows Super Admins to manually verify KYC/KYB documents for newly onboarded restaurants.
- Contains an **"Impersonate" Button:** Triggers a JWT payload injection allowing Customer Support staff to load up the `merchant-dashboard` UI acting precisely as the target merchant (for immediate troubleshooting without asking for passwords).

### 4. Global Financials & Risk
- **Master Ledger / PayFactor:** Controls exactly what percentage PaySurity extracts from Daily Batches before releasing funds via ACH. Controls immediate lock-downs for suspected fraud.
- **Compliance Tooling:** Auto-generates aggregated 1099-K CSVs and Form 941 matrices for the master accounting team.

### 5. Automated CI/CD & Test Runner
- Provides a UI wrapping the `AutomatedTestRunnerService`.
- Rather than demanding CLI commands, IT support staff can click **Run Production E2E Ping**. This triggers native `exec()` Jest validations against sandbox Gateways (FluidPay/Tax Engine) testing real-time connection stability outside of GitHub pipelines.

## 🛑 POST-AUDIT ADDENDUM (2026-08-06)
**STATUS: SEVERE DIVERGENCE DETECTED**

An independent architectural audit revealed that the current codebase (`apps/admin-portal`) completely fails to implement the strict security and feature requirements defined above.

1. **Vaporware Features:** The Automated CI/CD Test Runner (Sec 5), Physical Device Management (MDM Remote WebSocket) (Sec 2), and Global Telemetry Revenue/Affiliates dashboards (Sec 1) do not exist in the codebase.
2. **Client-Side Impersonation (Fraud Risk):** The "Impersonate" button in `tenants/table.client.tsx` simply writes `ps_impersonate_tenant_id` to `localStorage` and opens a new tab. This violates the mandated `x-impersonate-tenant` secure middleware tunnel and allows trivial client-side tampering of tenant context.
3. **Hardcoded Data:** The KYB Underwriting page (`merchants/page.tsx`) relies on a hardcoded `SEED_APPS` array, violating the `DEV_IMPLEMENTATION_STANDARD.md` mandate.
4. **Weak Client-Side Guards:** The operator console relies on `x-location-id` in the client's `document.cookie` or `sessionStorage` to enforce location-based access, inviting trivial bypass attacks.
5. **Missing RBAC:** `FINANCE_ADMIN` and `SUPPORT_ADMIN` boundaries are not properly enforced in the UI, and the PayFactor tool for controlling revenue extraction does not exist.

**MANDATE:** The Super Admin portal must undergo immediate remediation. The impersonation flow must be rewritten to use cryptographically secure backend JWT signing, and all hardcoded vaporware must be purged or actually built.
